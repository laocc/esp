# 关于ESP基本配置

以下所有示例，涉及目录的，称根目录的，均是指实际项目文件系统所在的根目录，不是操作系统的根目录。

## 环境要求

- PHP >= 8.1
- 扩展：`redis`、`json`、`libxml`、`xml`、`simplexml`、`mbstring`、`zlib`、`pdo`（见 `composer.json`）
- 依赖包：`laocc/helper`、`laocc/dbs`、`laocc/error`（composer 自动安装）

## 安装

```
composer create-project laocc/esp-install website
```

其中 `website` 为项目目录，可任意自定义。

或在已有项目的 `composer.json` 中引入：

```json
{
  "require": {
    "laocc/esp": "*"
  }
}
```

生产环境建议执行加载优化：

```
composer dump-autoload --optimize
```

安装脚本（`esp\scripts\Install`）会在 `composer install/update` 结束后自动检查并创建 `{_ROOT}/runtime` 目录。

## 入口及配置

nginx 示例：

```
server    {
    listen 80;
    server_name www.blog.com;
    index index.php;
    root /ROOT/public/www;
    include php.conf;
    access_log off;
}
server    {
    listen 80;
    server_name api.blog.com;
    index index.php;
    root /ROOT/public/api;
    include php.conf;
    access_log off;
}
```

这里 `root` 所指向的目录中：`/ROOT` 为根目录，`www` 和 `api` 为虚拟机，建议与虚拟机名同名，便于查找；
但实际虚拟机名称由 `_VIRTUAL` 决定，即下面 `(new \esp\core\Dispatcher($option, 'www'))->run();` 中的 `www`。

建议在 nginx 的 server 中屏蔽 `HEAD` 请求，或在非 `GET|POST` 时直接返回，框架遇到 `HEAD` 请求会直接 `exit('OK')`：

```
if ($request_method ~ ^(HEAD)$ ) { return 200 "OK"; }
```

`/ROOT/public/www/index.php`：

```php
<?php
$option = include_once(dirname(__DIR__) . '/option.php');
(new \esp\core\Dispatcher($option, 'www'))->run();
```

`/ROOT/public/option.php`：

```php
<?php
declare(strict_types=1);

ini_set('error_reporting', strval(E_ALL));
ini_set('display_errors', 'true');
ini_set('date.timezone', 'Asia/Shanghai');

try {
    (include(__DIR__ . "/../vendor/autoload.php")) or exit('Please RUN:<h3 style="color:red;">composer install</h3>');
} catch (\Error $error) {
    http_response_code(500);
    header("Status: 500 Internal Server Error", true);
    print_r($error);
    exit;
}

// 在这里放整个系统的相关设置或公共常量定义等
$option = array();

// 系统常量定义完成后，正式启动系统初始化时执行
$option['before'] = function (&$option) {
    define('_CONFIG_LOAD', _DEBUG);
};

// 系统初始化结束时执行
$option['after'] = function (&$option) {

};

return $option;
```

`$option` 中框架会读取的键：

| 键        | 说明                                                    |
|----------|-------------------------------------------------------|
| `before` | 系统常量定义完成后、初始化前执行，回调参数为 `&$option`                     |
| `after`  | 初始化结束时执行                                              |
| `config` | 传给 `esp\core\Configure` 的配置，见 [数据库](./4.databases.md) |
| `error`  | 传给 `esp\core\Handler` 的配置                             |
| `timer`  | 存在该项时创建 `esp\debug\Timer`，用于记录各阶段耗时                   |

CLI 入口（`/ROOT/public/cli/index.php`）内容与 web 入口基本相同，只是最后调用 `->run(true)` 或 `->simple()`：

```php
<?php
$option = include_once(dirname(__DIR__) . '/option.php');
(new \esp\core\Dispatcher($option, 'cli'))->simple();
```

框架自带 `esp.sh` 脚本可直接在项目任意目录执行 CLI 命令。

## 主要基本常量

| 常量            | 说明                                                                            |
|---------------|-------------------------------------------------------------------------------|
| `_ROOT`       | 项目根目录，由 `Dispatcher` 自动推算（依据 `vendor/laocc/esp/core` 的位置），也可在入口处自行定义          |
| `_RUNTIME`    | 临时文件目录，默认 `{_ROOT}/runtime`，此目录要加到 `.gitignore` 中，也可以指定到项目目录以外的任意目录           |
| `_UNIQUE_KEY` | `md5(core/Dispatcher.php)`，本项目在当前服务器的唯一键，redis 中所有系统键都以此为前缀                   |
| `_VIRTUAL`    | 虚拟机(子项目)，例如大项目下有 `www`、`admin`、`api` 等应用，这些是相对独立的子项目                          |
| `_MODULE`     | 虚拟机内还可以再分为不同模块，模块与虚拟机结构完全相同，见后面说明                                             |
| `_CLI`        | 当前实例是否运行在 cli 环境下                                                             |
| `_DEBUG`      | 当前服务器是否 debug(开发)环境，添加 `{_RUNTIME}/debug.lock` 即为 debug 环境，文件内容作为 `_DEBUG` 的值 |
| `_MASTER`     | 当前服务器是否群集主服务器，依据 `{_RUNTIME}/master.lock`                                     |
| `_DOMAIN`     | 当前访问的域名，取自 `HTTP_HOST` 去掉端口                                                   |
| `_HOST`       | 当前域名的根域名，默认由 `host(_DOMAIN)` 推算，可在入口自行定义，见后面说明                                |
| `_HTTPS`      | 当前是不是 https 方式访问                                                              |
| `_URL`        | 当前浏览器中完整的 URL                                                                 |
| `_URI`        | 当前请求的目标文件，系统路由即是根据此值分配的，即 `REQUEST_URI` 中的 path 部分                            |
| `_CIP`        | 当前访问者的 IP 地址                                                                  |

`{_RUNTIME}` 下用于控制行为的标记文件：

| 文件              | 作用                                                                                        |
|-----------------|-------------------------------------------------------------------------------------------|
| `debug.lock`    | 存在即为 debug 环境（ `_DEBUG` ）                                                                 |
| `master.lock`   | 存在即为主服务器（ `_MASTER` ），见 [群集服务](./12.cluster.md)                                           |
| `flush_key.txt` | 配合 URL 参数 `_flush_key` 强制刷新 config / 路由缓存，见 [数据库](./4.databases.md) 与 [路由](./5.routes.md) |

程序结构为：`虚拟机_VIRTUAL > 模块_MODULE > 控制器Controller - 数据模型Model > 动作Action > 视图View`，数据模型、视图，均由控制器派生出来。

### 目录结构

```
├── application            ;由 request.ini 中 directory 指定，默认 /application
│   └── www                ;虚拟机，与 _VIRTUAL 同名
│       ├── controllers
│       │   ├── _Base.php
│       │   └── IndexController.php
│       ├── models
│       └── views
│           ├── index
│           │   └── index.php
│           └── layout.php
├── common
│   ├── config             ;配置文件目录，由 $option['config']['path'] 指定
│   └── routes             ;路由表目录，由 request.ini 中 router 指定
├── public
│   ├── www/index.php      ;web 入口
│   ├── cli/index.php      ;cli 入口
│   └── option.php
└── runtime                ;临时目录，加入 .gitignore
```

### _VIRTUAL

程序可以有任意多个虚拟机，一般情况下一个虚拟机对应一个子站（一个入口 + 一个域名），虚拟机下可以添加多个模块。

### _MODULE

例如有项目：
员工管理系统，有员工`StaffController`、工作`JobsController`、考勤`TimerController`等控制器。
其中`JobsController`中涉及内容可能很多，不分模块时这个控制器会有很多 Action；
这种情况下，可以把 `jobs` 单独作为一个模块来对待，但模块下不能再有 `JobsController`。
目录结构如下：

```
├── controllers
│   ├── _Base.php
│   ├── StaffController.php
│   └── TimerController.php
├── jobs
│   ├── controllers
│   │   ├── ReportController.php
│   │   └── TypeController.php
│   └── views
│       ├── report
│       │   └── index.php
│       ├── type
│       │   └── index.php
│       └── layout.php
└── views
    ├── index
    │   └── index.php
    └── layout.php
```

请求路径：

- http://www.comp.com/staff/list
- http://www.comp.com/timer/list
- http://www.comp.com/jobs/report/list
- http://www.comp.com/jobs/type/list

判断规则（默认路由）：URI 第 1 段若能在 `{directory}/{virtual}/` 下找到同名目录，则该段为模块，第 2 段为控制器，第 3 段为动作；否则第
1 段为控制器，第 2 段为动作。详见 [路由](./5.routes.md)。

### _HOST

`_HOST` 是 `_DOMAIN` 的根域名，默认由 `host(_DOMAIN)` 推算，主要用于：

- Cookies 的作用域（ `cookies.ini` 中 `domain = host` 时，Cookie 写在根域下，各子域共享 ）
- 配置的多域名覆盖（ `Configure::mergeConf()` 按 `default` > `_VIRTUAL` > `_HOST` > `_DOMAIN` 顺序合并 ）
- 缓存的域名隔离（ `cache.ini` 中 `isolation = 1` ）

对于 `www.app.domain.com` 这种域名，若希望根域为 `app.domain.com` 而不是 `domain.com`，
`_HOST` 又必须在 `Dispatcher` 构造之前定义，所以在入口文件中要先于 `new Dispatcher` 手工定义：

```php
<?php
// public/www/index.php
define('_HOST', 'app.domain.com');
$option = include_once(dirname(__DIR__) . '/option.php');
(new \esp\core\Dispatcher($option, 'www'))->run();
```

同理，`_ROOT`、`_RUNTIME`、`_DEBUG` 等常量只要在 `new Dispatcher` 之前定义，框架都会直接采用而不重复定义。
