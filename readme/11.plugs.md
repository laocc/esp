# 关于插件`Plugs`和`bootstrap`

## bootstrap

`bootstrap` 是系统启动时的引导类，在 `run()` 之前注册：

```php
$option = include_once(dirname(__DIR__) . '/option.php');
$dis = new \esp\core\Dispatcher($option, 'www');
$dis->bootstrap(\library\Bootstrap::class);   //也可以传一个已实例化的对象
$dis->run();
```

- 框架会遍历 bootstrap 类中所有以 `_init` 开头的方法并依次调用，参数为 `Dispatcher` 自身；
- 任一 `_init` 方法返回 `false`，则 `Dispatcher::$run` 置为 `false`，`run()` 不再执行路由与分发，直接收尾；
- 注册插件（`setPlugin`）一般就放在 bootstrap 的某个 `_init` 方法里。

```php
namespace library;

use esp\core\Dispatcher;

class Bootstrap
{
    public function _initPlugin(Dispatcher $dispatcher)
    {
        $dispatcher->setPlugin(new Plugs());
    }

    public function _initConst(Dispatcher $dispatcher)
    {
        define('_PUBLISH_KEY', 'www_order');
    }
}
```

## 系统插件

- 插件类须继承自 `\esp\core\Plugin`，也可以实现 `\esp\face\PlugFace`（两者钩子名现已一致，均为 `router`…`end`）；
  继承 `Plugin` 时钩子有空实现，只覆盖需要的即可；实现 `PlugFace` 则六个方法都要写；
- 注册：`$dispatcher->setPlugin(new Plugs())`，或在入口直接：

```php
$dis = new \esp\core\Dispatcher($option, 'www');
$dis->setPlugin(new \library\Plugs());
$dis->run();
```

- 注册名 = 类名去掉命名空间后首字母大写，同名插件重复注册会报错；
- 控制器中取插件对象：`$this->getPlugin('Plugs')`，之后可直接调用插件自己的方法；
- 建议插件类写在命名空间里（注册名更明确，也避免与全局类重名）。

## 系统 HOOK

插件中可以实现以下 6 个方法，按触发顺序：

| # | 方法                                                 | 时机                                       | 返回值作用                        |
|---|----------------------------------------------------|------------------------------------------|------------------------------|
| 1 | `router(Request $request, Response $response)`     | 路由**之前**                                 | 非 null → 直接 display 并结束整个流程 |
| 2 | `dispatch(Request $request, Response $response)`   | 路由之后、控制器**之前**；若命中了缓存则不会进入这里            | 非 null → 直接 display 并结束整个流程 |
| 3 | `display(Request $request, Response $response, &$value)` | 控制器执行之后、输出之前，`$value` 为控制器返回值      | 非 null → 直接 display，并**跳过 `finish`** |
| 4 | `finish(Request $request, Response $response, &$value)` | 输出之后、`fastcgi_finish_request()` 之前    | 忽略                           |
| 5 | `shutdown(Request $request, Response $response, &$value)` | `end:` 处、`register_shutdown_function()` 之前 | 忽略                      |
| 6 | `end(Request $request, Response $response, &$value)` | `run()` 最末尾                              | 忽略                           |

- 第 3/4/5/6 个钩子的 `$value` 是引用，可以在钩子里修改最终显示的内容；
- 第 1/2/3 个钩子返回**非 null** 时，框架把该返回值直接交给 `Response::display()` 并 `goto end`，
  之后的钩子不再执行（第 5、6 个仍会执行）；
- 第 2 个钩子名为 `dispatch`，但它是在**控制器之前**触发的，命名与语义不符，使用时留意。

```php
namespace library;

use esp\core\Plugin;
use esp\core\Request;
use esp\core\Response;

class Plugs extends Plugin
{
    public function dispatch(Request $request, Response $response)
    {
        //路由已完成，注册标签解析器的最佳位置
        $response->registerAdapter(new Adapter());
    }

    public function end(Request $request, Response $response, &$value)
    {
        //客户端已断开，这里适合做耗时的事
    }
}
```

### 执行细节

1. 注册多个插件时，`plugsHook()` 会**按注册顺序依次调用**所有实现了该钩子的插件；
   其中任一个返回非 null 时立即中断，不再调用后面的插件；
2. `run(true)` 与 `simple()`（即 CLI 入口）下，所有钩子都被 `!$simple` 挡住，**一个都不会执行**；
3. 第 3/4/5/6 个钩子的 `$value` 是引用，前一个插件的修改对后一个插件可见。

## 与 bootstrap 的区别

- `bootstrap` 只在启动时执行一次，用于初始化常量、注册插件、注册监听等；
- `Plugin` 的 HOOK 在每次请求的执行过程中按阶段被触发。
