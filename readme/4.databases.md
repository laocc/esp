# 关于数据库`Mysql`及`Redis`

MySQL 的具体操作（查询构造、事务等）由 `laocc/dbs` 提供，本框架负责的是**配置、连接与缓存键的管理**。

## 配置文件 database.ini

位于 `common/config/database.ini`，完整示例见 [数据模型](./3.models.md)。
要点：

- `[mysql]` 为主库配置，`master` 可以是 socket 文件路径，也可以是 `host:port`；
- `[redis]` 为 redis 配置，`host` 以 `/` 开头时按 unix socket 连接；
- `db` 可以是整数，也可以是数组（`db[config]`、`db[model]`、`db[session]`）；
- `mysql.cache` 决定 Model 查询结果是否自动缓存到 redis，以及缓存方式。

## Redis

框架在 `Configure` 构造时就连接了 redis，并把它挂在多个位置：

```php
$this->_redis;                        //控制器中，= Configure::_Redis
$this->_config->_Redis;               //Configure 上
$this->_config->select($dbID);        //切换库，不传参时切回 config 所在库
$this->_config->reConnectRedis();     //CLI 长驻进程中重连
```

系统自身占用的 redis 键（全部以 `_UNIQUE_KEY` 为前缀，`_UNIQUE_KEY = md5(esp/core/Dispatcher.php)`）：

| 键 | 内容 |
|---|---|
| `{_UNIQUE_KEY}_CONFIG_` | 全站配置缓存 |
| `{_UNIQUE_KEY}_MYSQL_CACHE_` | Model 数据缓存 |
| `{_UNIQUE_KEY}_RESOURCE_RAND_` | 资源版本号，用于刷新静态资源 |
| `{_UNIQUE_KEY}_HASH_` | hash 表，由 `$option['config']['hash']` 指定的目录载入 |

## 缓存清理

CLI：

```
esp -s flush [lev] [safe]
```

`lev` 按位相加：

| 值 | 作用 |
|---|---|
| 1 | 清 `_CONFIG_`（默认） |
| 2 | 清 `_MYSQL_CACHE_` |
| 4 | 清 `_RESOURCE_RAND_` |
| 8 | 清 `_HASH_` |
| 32 | 清路由缓存文件 |
| 256 | 清空整个 redis 当前库，保留 `_RESOURCE_RAND_` |
| 1024 | 清空整个 redis，第 2 个参数必须等于 `flushAll` |

也可以在 URL 中带参数清理：

```
?_flush_key=XXXX&_config_load=NNN    ;XXXX 为 {_RUNTIME}/flush_key.txt 的内容，NNN 为上面的值（不含 1024）
?_flush_key=XXXX&_router_load=NNN    ;NNN & 32 时清空所有路由缓存
```

注意：config 的判定是「传入的 `_flush_key` 与 `flush_key.txt` 内容**一致**才刷新」；
而路由的判定目前是「**不一致**才刷新」，两者相反，使用时以实际效果为准。

其它 CLI 命令：

```
esp -s config [key] [toJson]   ;查看 config
esp -s resource                ;重置资源版本号
```

## 配置缓存与 _CONFIG_LOAD

`Configure::forceCache()` 决定是否读取缓存：

- `_DEBUG` 为真时不读缓存；
- 若定义了常量 `_CONFIG_LOAD`，则 `forceCache() === !_CONFIG_LOAD`。
  典型写法是在 `option.php` 的 `before` 中 `define('_CONFIG_LOAD', _DEBUG)`，即开发环境下每次都从文件重新加载，生产环境读缓存；
- 也可定义 `_DISABLE_CONFIG_CACHE`。

配置默认以 **redis** 方式保存（`$option['config']['type'] = redis`），也可以改为 `file`（保存在 `{_RUNTIME}/{_UNIQUE_KEY}_CONFIG_.json`）。

配置项：

```php
$option['config'] = [
    'path'     => '/common/config',  //配置文件目录
    'type'     => 'redis',           //redis 或 file
    'folder'   => 'www',             //子目录，同名文件覆盖主目录中的值（多站点共用一套配置时用）
    'extra'    => ['/common/extra'], //额外的配置文件目录
    'hash'     => ['/common/hash'],  //这些目录下的文件载入到 redis 的 _HASH_，用 $config->hash(KEY) 读取
    'merge'    => [],                //直接并入 config
    'replace'  => [],                //递归替换 config
];
```

## mysql组合条件

`where` 数组的组合规则：

1. 下标为字段名（键值对）的，相互之间是 **and**；
2. 下标为整型（即 `$where[] = ...`）的单元：
   - 单元内是键值对（关联数组）的，相互之间是 **or**；
   - 单元内是数组（列表）的，列表各元素之间是 **and**。

```php
$where = [];

//这两项之间是 and
$where['expUserID'] = $this->userID;
$where['expUserLabel'] = $label;

//整型下标：单元内这两个键之间是 or
$where[] = [
    'expUserID' => $this->userID,
    'expSignUserID' => $this->userID,
];

$where[] = [
    ['expCreateTime>' => time()],
    [
        //这个单元内两项之间是 or
        ['expSupplement>' => 0, 'expPackingFee>' => 0],
        //与上面这一行是 and
        'expSupID' => 0,
    ],
];
```

最终条件相当于：

```
expUserID=? and expUserLabel=? and (expUserID=? or expSignUserID=?)
and expCreateTime>123123 and expSupID=0 and (expSupplement>0 or expPackingFee>0)
```

字段名后可跟比较符，如 `expCreateTime>`、`expUserID>=`、`expName like` 等。
