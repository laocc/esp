# 群集服务

多台服务器共用一个 redis 与一套 config 时，只有**主服务器**从文件加载配置并写入 redis，
从服务器一律从 redis 读取；读不到时，从服务器会反向请求主服务器重新加载一次。

## 配置 cluster.ini

```ini
run = true

;主服务器 IP
master = 192.168.111.111

;从服务器 IP，有几个设几个，外网内网均可，只要主服务器能连通
slave[] = 192.168.2.4
slave[] = 192.168.2.6
```

主服务器 IP 的设置方式：

1. 若所有从服务器和主服务器在同一内网，只需把主服务器设成内网 IP；
2. 若从服务器和主服务器全都是外网，主服务器设成外网 IP；
3. 既有内网也有外网时，则需要将 master 设为数组：`public` 和 `private`，分别为外网、内网 IP。

## 标记主服务器

在主服务器的 `{_RUNTIME}` 下创建 `master.lock` 文件，从服务器都不用创建。
框架据此定义常量 `_MASTER`。

**改变 config 值只能在主服务器上进行**（从服务器只从 redis 读）。

## 从服务器的唤醒机制

1. 从服务器启动时先读 redis 中的 `{_UNIQUE_KEY}_CONFIG_`；
2. 读不到时，向主服务器发一个 HTTP 请求：`http://{host}/_esp_config_awaken_`，
   UA 为 `espConfigAwaken`，用于唤起主服务器重新初始化 config；
3. 主服务器收到该请求后直接返回 `_UNIQUE_KEY`（redis 驱动）或整个 config 的 json（file 驱动）；
4. 从服务器再次从 redis 读取。

因此需要在入口或公共位置定义常量 `_RPC`：

```php
//字符串形式：主服务器 IP
define('_RPC', '192.168.111.111');

//数组形式：可指定域名、端口
define('_RPC', ['host' => 'rpc.esp', 'port' => 800, 'ip' => '192.168.111.111']);
```

默认 `host = rpc.esp`、`port = 800`。
**需要在 nginx 中建立一个绑定该域名和端口的虚拟机，指向任意一个虚拟机入口即可**：

```
server {
    listen 800;
    server_name rpc.esp;
    index index.php;
    root /ROOT/public/www;
    include php.conf;
    access_log off;
}
```

## CLI 限制

CLI 下若定义了 `_RPC` 且当前不是主服务器，框架级系统方法（`-s` 开头的命令）会被拒绝执行，
返回：`框架级系统方法只能在主服务器执行`。

## 常量与类

| 常量/类 | 说明 |
|---|---|
| `_MASTER` | 当前是否主服务器 |
| `_RPC` | 主服务器地址，未定义则不启用从服务器唤醒 |
| `_UNIQUE_KEY` | 本项目的唯一键，主服务器返回它作为校验 |

> `esp\core\Cluster` 类目前为空实现，群集相关行为由 `Configure` 与 `Dispatcher` 完成。
