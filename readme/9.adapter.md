# 关于标签解析器`Adapter`

标签格式由解析器自己决定，框架只在渲染视图时把工作转交给它。以 Smarty 为例，只要写一个实现 `esp\face\Adapter` 的类即可。

## 接口

```php
namespace esp\face;

interface Adapter
{
    public function assign(array|string $name, $value = null);
    public function fetch(string $file, array $value): string;
    public function display(string $file, array $value): mixed;
}
```

- `assign()`：送入变量，参数为数组时须自行转成键值；
- `fetch()`：解析视图并返回内容；
- `display()`：解析视图并直接打印。

## 注册方式一：配置文件（推荐）

在 `response.ini` 中配置：

```ini
adapter[class] = \library\Adapter
adapter[cache] = {_RUNTIME}/cache
adapter[layout] = true
adapter[delimiter.0] = {{{
adapter[delimiter.1] = }}}
```

| 项        | 说明                                          |
|----------|---------------------------------------------|
| `class`  | 解析器类名，不以 `\` 开头时会自动补上                       |
| `cache`  | 编译缓存目录，目录不存在时回退到 `{_RUNTIME}/cache`         |
| `layout` | 是否对 layout 也启用解析器，默认 `false`，即**默认只对子视图有效** |
| 其它       | 会一并原样传给解析器的构造函数所在配置，可在自己的类中读取               |

> 框架自带的 `common/config/response.ini` 示例中 `adapter[class] = \Smarty`，若项目未安装 Smarty 请改成自己的类或整段注释掉。
> `class` 为 `\Smarty` 时，框架会自动调用 `setCompileDir()` 设置编译目录。

## 注册方式二：插件中注册

在插件的 `dispatch` 钩子中注册（此时路由已完成，`router` 钩子是在路由之前触发的，不适合）：

```php
class Plugs extends \esp\core\Plugin
{
    public function dispatch(Request $request, Response $response)
    {
        $response->registerAdapter(new \library\Adapter());
    }
}
```

入口中注册插件：

```php
$option = include_once(dirname(__DIR__) . '/option.php');
$dis = new \esp\core\Dispatcher($option, 'www');
$dis->setPlugin(new \library\Plugs());
$dis->run();
```

注意：`registerAdapter()` 要求 `$request->virtual` 已有值，否则报
`registerAdapter要在routeAfter之后执行`（该提示文案沿用了旧钩子名，实际含义是"要在路由之后执行"）。
另外，若命中页面缓存则不会走到 `dispatch` 钩子——不过那种情况下也不会渲染视图，不受影响。
钩子清单见 [插件](./11.plugs.md)。

## 运行时控制

```php
$this->setAdapter(false);     //当前请求关闭解析器，改用原生 PHP 渲染
$this->setAdapter(true);      //重新开启；若从未注册过则报错"标签解析器没有注册"
$this->getAdapter();          //取解析器对象，可继续 assign
```

## 变量传送

```php
$this->assign($name, $value);             //Response，最终并入子视图，优先级最高
$this->getView()->assign($name, $value);  //View
$this->getAdapter()->assign($name, $value);//直接送给解析器
```

启用解析器时的实际流程（`View::fetch()`）：

1. 先 `$adapter->assign(View 自己的变量)`；
2. 再 `$adapter->fetch($file, Response 变量 + View 变量)`。

也就是说 **第二个参数里的变量需要解析器自己在 `fetch()` 中分配出去**，否则视图里只能看到第 1 步 assign 进去的那些值。
用 Smarty 这类 `fetch()` 不接收变量的解析器时，请统一用 `$this->getView()->assign()` 或 `$this->getAdapter()->assign()`
送值。

## layout

默认解析器只作用于子视图。若希望 layout 中的标签也被解析，设置 `adapter[layout] = true`；
此时框架会对 layout 也 `registerAdapter()`。

## 关闭解析器后的变量

`$this->setAdapter(false)` 只是不再调用解析器，变量本身仍会 `extract()` 后传入视图，
但通过 `$this->getAdapter()->assign()` 送进去的值不会跑到子视图中——它们只存在于解析器对象里。
