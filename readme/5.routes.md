# 关于路由`Router`

## 默认路由规则

框架默认拆分 `_URI` 后按先后顺序指定为控制器和动作：

`http://admin.open.com/debug/test/ab/c/d`，拆分 `/debug/test/ab/c/d`：

- 若 `{directory}/{virtual}/debug` 是目录 → module=`debug`，controller=`test`，action=`ab`，params=[c,d]
- 否则 → controller=`debug`，action=`test`，params=[ab,c,d]

URI 为 `/` 或空时，controller=action=`index`。

## 路由表

- 路由表目录由 `request.ini` 中 `router` 指定，默认为 `/common/routes`；
- 目录下按虚拟机分别创建文件，`default.ini` 为通用规则，`www.ini` 对应 `www` 虚拟机；
- 格式支持 `.ini`、`.json`、`.php`，只要最终解析成一个数组即可；
- 合并方式为 `default.ini` 的内容 `+` 虚拟机文件的内容，因此**同名键以 `default.ini` 为准**，请避免两边用相同的规则名；
- 键名以 `#` 开头的是注释，会被跳过。

```ini
[debugs]
uri = /debugs
route[virtual] = 1
route[module] =
route[controller] = 2
route[action] = 3
map[] = 5
map[] = 4
```

### 匹配方式（一条规则内只能有一种生效）

| 键 | 含义 |
|---|---|
| `path` | 与 `_URI` 完全相等 |
| `uri` | `_URI` 以此值开头 |
| `like` | `_URI` 中包含此值 |
| `match` | 用正则匹配 `_URI` |
| `__default__` | 默认路由，放在规则组的最后 |

同一条规则里同时写了多个时，检查顺序为 `path > uri > like > match`；
但**规则之间的优先级是路由表文件内的先后顺序**，第一条匹配上的规则即生效，后面的不再检查。

### method 请求方式限制

```ini
method[] = get
method[] = post
```

可选 `get`、`post`、`ajax`、`all`、`cli`，不符合的一律返回 `Illegal Method`。
`ALL` 等价于 `GET,POST,CLI`；`HTTP`/`AJAX` 按当前是否 ajax 展开为 `GET,POST`。

### route 路由结果转换

```ini
route[virtual] = 1
route[namespace] =
route[directory] = /application
route[module] = 2
route[controller] = 3
route[action] = 4
```

- 四个常用子项：`virtual`、`module`、`controller`、`action`；
- 值可以直接写字符串，也可以写成 `=2` 这种数字形式，表示取 URI 拆分结果（或 `match` 正则匹配结果）的第 n 项；
- `module`、`controller`、`action` 不写时默认为 `index`；
- `virtual`、`directory` 写在 `route` 内外都可以，`route` 内的优先；
- 值为数字但对应下标不存在时，也退化为 `index`。

### map 参数

```ini
map[] = 5
map[] = 4
```

- `map` 分配的是控制器方法的实参；
- `map[] = 5` 为位置参数，值是 URI 拆分结果的下标（也可以是 `$5` 这种写法）；值不是数字时，原样作为实参传入；
- `map[name] = 2` 为**命名参数**，此时控制器方法必须有完全对应的参数名，数量也必须相同；
- 不写 `map` 时，参数取 `controller/action` 之后的全部；
- 只要没有出现命名参数（写了 `map[]` 也算），参数都会用 `null` 补齐到 10 个，即实际传入方法的参数总共为 10 个。

```php
//map[name] = 2 时
public function indexGet(string $name)
```

### view 视图设置

路由中可以直接指定视图：

```ini
view[path] =
view[file] =
view[layout] =
```

### return 直接返回

若配置了 `return`，则除 `method` 外的其它设置全部无效，直接返回该值：

| 值 | 行为 |
|---|---|
| `http://` 或 `https://` 开头 | 301 跳转到该 URL |
| `redis:KEY` | 读取 redis 中 KEY 的值，`text/plain` |
| `/` 开头，或 `files:` 开头 | 包含该文件（路径基于 `_ROOT`，必须在 `_ROOT` 之内且是文件），`text/html` |
| `{` 开头 | 原样输出，`application/json` |
| 其它 | 原样输出，`text/plain`，其中的 `\r`、`\n` 会被换成换行 |

`return` 中的 `${n}` 会被替换为匹配结果的第 n 项。

```ini
[robot]
path = /robots.txt
return = User-agent: *\nDisallow: /
```

## URI 安全校验

参与路径/类名拼接的 URI 段（第 1 段起，默认到第 3 段；若 `route` 中给 `module`/`controller`/`action` 指定了更大的下标则相应放宽）会被统一校验：

- 只允许 `字母数字下划线`、`中文`、`.`、`-`；
- 含 `..` 的一律拒绝（挡住目录回退）；
- 以点开头或结尾的拒绝（挡住 `.env` 之类）。

不合法时返回 `Illegal Uri`。参数段（可能是中文、邮箱、url 编码等）不参与路径拼接，不做限制。

## 别名 alias

有两种别名机制：

1. `request.ini` 中的控制器别名，只映射控制器名：

```ini
[www]
alias[aaa] = bbb    ;请求 /aaa 实际由 BbbController 实现
```

注意：启用 Cache 时缓存键按 `bbb` 生成，而生成静态 html 仍按 `aaa` 命名。

2. 顶层 `alias`（可建一个 `common/config/alias.ini`），可映射 1~4 段：

```ini
alias[index][list] = index/list          ;1段：只换 action
alias[index][list] = news/index          ;2段：换 controller/action
alias[index][list] = jobs/news/index     ;3段：换 module/controller/action
alias[index][list] = www/jobs/news/index ;4段：连 virtual 一起换
```

## 允许与禁止的控制器

`request.ini` 中：

```ini
allow[] = index      ;只允许这些控制器（排他性），优先于 disallow
disallow[] = test    ;禁止这些控制器
```

不符合的直接返回 `'... not exist in allowed'` 或 `disallow`。

## 空控制器/空动作

`request.ini` 中的 `empty` 指定找不到控制器或动作时的返回内容（否则返回 `[xxx] nonexistent`）：

```ini
empty[default] = 页面不存在
empty[www] = /404.html
```

## 虚拟机转换

例如现有虚拟机 `admin`、`www` 和 `tools`，现想把 `tools` 作为 `admin` 下面的一个模块 `module`，正常的文件应该是 `application/admin/tools`，
也可以把 `tools` 当成一个单独的模块写代码，通过路由表的形式转换，也就是把 `/tools` 开头的 URL 中原本 module 值提升为 virtual 值：

```ini
[tools]
uri = /tools
route[virtual] = 1
route[module] = ;module要置为空值，或不写这项
route[controller] = 2
route[action] = 3
```

## 路由缓存

解析结果会缓存到 `{_RUNTIME}/_ROUTES_{md5}#{_VIRTUAL}.route`，CLI 与 debug 环境下不读缓存。

清理方式：

```
esp -s flush 32                              ;CLI
?_flush_key=XXXX&_router_load=32             ;URL，XXXX 为 {_RUNTIME}/flush_key.txt 的内容
```

## 路由结果

解析完成后写入 `Request`，可用 `$this->_request->RouterValue()` 查看：

```
label      命中的规则名
virtual    虚拟机
method     请求方式
module     模块
controller 控制器
action     动作
exists     是否正常命中
params     参数
```

`_MODULE` 常量也是在路由完成时定义的。
